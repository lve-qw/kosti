# Сценарий демонстрации и защиты

## 1. Задача — 30 секунд

Сервис принимает DICOM/ZIP и возвращает по каждому файлу девять обязательных
полей. Он различает две области и пять типов нарушений. Один повреждённый файл
не прерывает пакет. Технический Success означает успешное вычисление, не
подтверждение правильности медицинского решения.

## 2. Данные — 40 секунд

499 файлов сведены к 252 уникальным изображениям только для обучения;
при экспорте дубли остаются отдельными строками. Исследования и совпадающие
пиксели объединены до разделения на три фолда. Неизвестные метки маскируются.
Качество взято из экспертного Excel, анатомическая индексация выполнена ИИ.
19 снимков бедра имеют неизвестную сторону. Это ограничение показано явно.

## 3. Выбор модели — 50 секунд

Сравнили ResNet18 без балансировки, ResNet18 с train-only весами классов
и frozen DINOv2. Выбрали balanced ResNet18: macro-F1 0.290 против 0 и 0.246.
Пороги фиксированы 0.5; внешний fold не используется для их подбора.
Совместная голова анатомии дала OOF accuracy 1.000, общий класс — F1 0.444,
ROC-AUC отдельной головы — 0.652. Оценка development-набора не заменяет внешнюю
валидацию. Слабое место — ось позвоночника (F1 0.059).

## 4. Живой показ — 60 секунд

1. Запустить сервер с `models/manifest.json` из архива (START_HERE.md).
2. Открыть страницу и показать «Модель подключена».
3. Выбрать согласованный локальный архив с DICOM и повреждённым файлом.
4. Показать список результатов, изображение, регион, вероятность, типы.
5. Открыть карточку повреждённого файла: Failure без выдуманных предсказаний.
6. Выгрузить CSV и показать ровно девять столбцов и по строке на каждый файл.
   Если встроенный браузер не сохраняет файл, использовать `/v1/batch` через
   curl из README; получение и содержимое ZIP проверены локально.

Не демонстрировать персональные исходные данные внешней аудитории без
согласованного допуска. Локальная тестовая пара в artifacts/demo обезличена,
но в распространяемый код и релизный архив изображения не включены.

## 5. Надёжность и ограничения — 40 секунд

499 файлов × 2 прохода, ноль технических сбоев, одинаковые предсказания.
Около 11 секунд на набор на CPU Mac, максимум 0.59 секунды на исследование;
полный замер набора на H200/Linux не выполнен. Linux/CPU Docker проверен
отдельным запуском и DICOM smoke-тестом; это не полный нагрузочный замер.
Инференс проверен с запретом исходящих сокетов.

Геометрические углы и сантиметры не выводятся: нет проверенного масштаба,
ориентиров и определения ROI. Следующий этап — улучшение слабых классов,
независимая проверка индексации, внешний тест и целевая контейнерная проверка.
Не утверждать, что технически работающий сервис уже достиг медицинского
качества или полностью прошёл приёмку хакатона.
