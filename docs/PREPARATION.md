# Подготовка данных и оценка без обучения

Команды не создают модель и не запускают оптимизацию. Им не нужен PyTorch.
Все пути ниже отсчитываются от корня клона SourceCraft; исходные данные после
очистки старого кода остались в родительской папке. Пакет предварительно установить:

```bash
python -m pip install -r requirements-core.lock
python -m pip install --no-deps .

python -m kosti.cli audit ../data/Исследования \
  --labels ../data/разметка.xlsx --output artifacts/audit.json
python -m kosti.cli annotation-template artifacts/audit.json \
  --output artifacts/annotations.csv
```

## Ручная проверка CSV

Шаблон содержит **каждый** декодированный файл, включая копии. Идентификаторы
`path,study_uid,image_uid,pixel_hash` менять нельзя. Заполнить:

- `region`: `spine` или `hip`, только после просмотра изображения.
- `side`: пусто для позвоночника, `left` / `right` для бедра.
- `label_source`: источник и способ проверки, например имя таблицы, номер
  Excel-строки и отметка экспертной проверки. Не включать персональные данные.
- `reviewed`: `1`, когда соответствие изображения и разметки проверено.
- Семь меток: `spine_position,spine_axis,spine_artifact,hip_position,hip_roi,spine_quality,hip_quality`.
  `1` означает нарушение/некачественное изображение, `0` — отсутствие нарушения.
  Неизвестные и неприменимые метки оставить пустыми. Даже после проверки часть
  меток может остаться неизвестной; проверка не означает, что все они известны.

Excel не соединяется с изображениями автоматически: сначала необходимо подтвердить
область и сторону. Противоречия качества и нарушений требуют экспертного решения;
скрипт не исправляет их автоматически. Разные метки у точных копий блокируют экспорт.
Сам CSV хранит заявление о проверке, а не доказательство её медицинской корректности.

## Фиксация разбиения

```bash
python -m kosti.cli prepare-folds artifacts/audit.json \
  --annotations artifacts/annotations.csv --n-splits 3 --seed 42 \
  --output artifacts/folds.json
```

Обязательно покрыть весь аудит и устранить ошибки декодирования. Все исследования,
связанные UID или точными копиями пикселей, объединяются **до** удаления дублей.
На каждый уникальный массив пикселей остаётся один sample, а `copies` сохраняет
идентификаторы исходных файлов. Nullable-метки сохраняются как JSON `null`.
`label_source` относится к выбранному sample; полный CSV остаётся первичным
источником происхождения разметки всех копий.

Проверить `fold_counts` до обучения: группы не стратифицируются, редкие позитивы
могут отсутствовать в отдельных фолдах. Внешний fold используется только для
оценки; пороги и гиперпараметры выбираются внутри обучающей части. StudyUID не
гарантирует отсутствие одного пациента в нескольких исследованиях.

Ни шаблон, ни фиксированный манифест, ни отчёт метрик не перезаписываются.
Для повторного запуска укажите новый путь. Не правьте аудит и CSV независимо:
после изменения набора сформируйте новый аудит и повторите проверку.

## Оценка готовых вероятностей

Будущий обучающий скрипт должен сформировать CSV с одним предсказанием для каждого
sample из манифеста. Заголовок и порядок обязательны:

```text
pixel_hash,fold,spine_position,spine_axis,spine_artifact,hip_position,hip_roi,spine_quality,hip_quality
```

Вероятности — конечные числа от 0 до 1 для всех семи выходов; `fold` совпадает
с манифестом. Нужны предсказания модели, которая не обучалась на этом fold.

```bash
python -m kosti.cli evaluate artifacts/folds.json \
  --predictions artifacts/oof.csv --output artifacts/metrics.json
```

Отчёт содержит F1, ROC AUC, average precision, sensitivity, specificity,
balanced accuracy и числа TP/FP/TN/FN. Неизвестные метки исключаются из расчёта.
Неопределённые метрики представлены `null`. Порог фиксирован на 0.5; калибровка
не выполняется. `macro_f1` усредняет все определённые семь меток, включая две
метки общего качества; отдельная macro-F1 пяти нарушений находится в `violations.macro_f1`.
Совпадение номера fold проверяется, история обучения модели технически не проверяется.

Данные, ручная разметка и выходы остаются в игнорируемом `artifacts/`; в Git
публикуются только код, инструкции и тесты на синтетических записях.
Обучающий entrypoint описан в [TRAINING.md](TRAINING.md); обучение не запускалось.
Обученные веса и подтверждённые метрики качества остаются следующим этапом.
Эти команды закрывают подготовку инструментов, а не DATA-03/ML-04.
