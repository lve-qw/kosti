# Локальный исследовательский комплект — 27 сентября 2026

Сервис теперь работает с реально обученными весами. Готовность программного
контура не означает достаточное качество распознавания: модель остаётся
исследовательским прототипом, особенно слабым на нарушении оси позвоночника.

## Проверенные данные и протокол

499 файлов, 252 уникальных изображения: 99 позвоночника, 153 бедра.
Экспертные оценки перенесены из исходного Excel, визуальная индексация анатомии
выполнена ИИ 24 сентября; независимой экспертной проверки индексации нет.
Для 19 изображений бедра сторона не установлена: используются только метки,
совпадающие для левой и правой стороны. Конфликты не заменены нормой.

Три фиксированных фолда объединяют связанные исследования и точные дубли;
размеры отложенных частей — 83/85/84. Модель каждого фолда не обучалась на его
изображениях. Надёжное разделение по пациентам не подтверждено.
ResNet18 ImageNet, замороженный encoder, 10 эпох, AdamW, learning rate 0.001,
batch size 16, seed 42. Семь бинарных выходов и два логита анатомии.
Балансировка: вес положительного класса равен negative/positive **только
на обучающей части**. Пропущенные метки исключены из функции потерь.
Пороги 0.5 фиксированы; по внешним фолдам они не подбирались.

## Сравнение с DINOv2

Проверен frozen ViT-S/14 из [официального DINOv2](https://github.com/facebookresearch/dinov2),
commit `7764ea0f912e53c92e82eb78a2a1631e92725fc8`. Те же фолды, предобработка,
10 эпох линейной головы, balanced BCE и фиксированные пороги 0.5.
Macro-F1 пяти нарушений 0.246 против 0.290 у balanced ResNet18;
анатомия 1.000 у обоих. Macro-F1 по фолдам:

| Энкодер | Fold 0 | Fold 1 | Fold 2 |
|---|---:|---:|---:|
| ResNet18 | 0.144 | 0.413 | 0.253 |
| DINOv2 | 0.319 | 0.295 | 0.122 |

Устойчивого улучшения нет, поэтому DINOv2 исключён из рабочего сервиса согласно
условию прекращения экспериментов. Головы, OOF и протокол сохранены в
`artifacts/dinov2-comparison-20260927/`. Это экспериментальные головы, а не
совместимый с сервисом quality-bundle.

## Проверка программного контура

- Все 499 файлов обработаны дважды без технических ошибок, результаты совпали.
- На macOS ARM64, Python 3.13.5, CPU: 11.41 и 10.88 секунды на набор;
  максимум 0.59 секунды суммарно на исследование из предоставленных файлов.
- Загрузка модели 1.05 секунды; пиковый RSS процесса около 397 MiB.
- Настоящие обезличенные DICOM прошли API/ZIP/CSV/превью с обученной моделью.
  Повтор сохранён отдельной строкой, повреждённый файл получил Failure.
- В проверке загрузки модели и API запрещены исходящие socket.connect;
  вызовов сети не потребовалось.
- Интерфейс проверен в браузере: выбор ZIP, обработка, два превью и отдельная
  карточка ошибки. Файл CSV проверен через ответ API; событие скачивания
  в инструменте встроенного браузера не подтвердилось.

Локальные замеры производительности не доказывают скорость на H200. Отдельный
Linux/CPU Docker-запуск подтверждён 27 сентября 2026 года.

## Проверка Linux/Docker и публичный стенд

- Ubuntu 24.04 x86_64, Docker 29.1.3, CPU, лимит контейнера 2 GiB.
- Образ собран из `Dockerfile` с `INSTALL_ML=1`; bundle смонтирован только для чтения.
- Контейнер работает от непривилегированного пользователя, с read-only rootfs,
  временным `/tmp`, ограничением процессов и политикой `unless-stopped`.
- `GET /`, `/health`, `/ready` и `POST /v1/review` проверены; DICOM обработан
  со статусом `Success`, девять колонок контракта и PNG-превью присутствуют.
- Во время одиночного smoke-теста контейнер использовал около 278 MiB RAM.
- Публичный стенд: `http://158.160.203.10:8000/`.

Это проверка воспроизводимости и программного контура, а не клиническая
валидация модели и не замер на GPU/H200.

## Незакрытые критерии плана

1. Независимая проверка анатомии/стороны и спорных экспертных меток.
2. Надёжное распознавание всех пяти нарушений; особенно оси позвоночника.
3. Разметка ориентиров и подтверждение физического масштаба для углов/ROI.
   Непроверенные линии и сантиметры не добавлены в результаты.
4. GPU/H200-запуск и замер на целевой конфигурации. Linux/Docker CPU-контур
   проверен отдельно; CUDA и H200 не проверены.
5. Внешняя валидация, калибровка на отдельном наборе и окончательная защита.

Kaggle API 27 сентября не предоставил доступ к подготовленному kernel;
поэтому расчёты выполнены локально. Новые медицинские данные не загружались.
