Дата: 21 сентября 2026. Локальная среда: macOS ARM64, Python 3.13.5, CPU, PyTorch 2.6.0 / torchvision 0.21.0.

## Подтверждено выполнением

- `python -m pytest -q`: **75 passed**, без пропусков, 3,56 секунды в последнем прогоне. Одно предупреждение об устаревающем alias BlockingPortal в стороннем Starlette TestClient; на результаты не влияет.
- `pip check`: No broken requirements found.
- `sh -n scripts/build.sh scripts/run.sh`: синтаксис корректен.
- CLI установлен обычным wheel и запущен вне исходного каталога. На этой macOS скрытый атрибут `.pth` мешал editable-install; обычная установка решила проблему. Добавлен регрессионный тест установленного entrypoint.
- `kosti audit data/Исследования --labels data/разметка.xlsx --output artifacts/audit.json`: 499 файлов, 499 декодированы, 0 ошибок, 100 исследований, 252 уникальных пиксельных массива, 247 повторных файлов.
- Исходный `model_classifaer.pth` загружен через `torch.load(weights_only=True, map_location='cpu')` и строгий `load_state_dict` в ResNet18: conv1 64×3×7×7, fc 2×512. Это проверка совместимости архитектуры, не точности классификации.
- Реальный HTTP-запуск установленного CLI: `/health` → 200; `/ready` → 503 без quality-model. Проверочный процесс после запроса остановлен.
- Сквозной тест: настоящий синтетический DICOM → локальный PyTorch state_dict → forward → multipart ZIP API → CSV с точным порядком полей. Проверены два файла с повторёнными пикселями и отдельная строка Failure для повреждённого файла. Веса в тесте искусственные и не являются медицинской моделью.

## Что покрывают тесты

Нормализация и инверсия DICOM; rescale перед windowing; padding; отсутствующие UID; неподдерживаемые представления; точные дубли; пропуски и противоречия Excel; транзитивная группировка исследований/дублей; метрики и маскирование неизвестных меток; проверка явной конфигурации модели и SHA256; несовместимые головы модели; API без модели; лимиты запросов и ZIP; обход каталогов; очистка временных файлов; изоляция ошибок; сохранение доступных UID; кириллица и повторные имена; CSV/XLSX; установленный CLI.

## Ещё не подтверждено

- Качество и калибровка модели: обученных quality-весов нет, F1/AUC проекта не получены.
- Предобработка и порядок классов исходного anatomy-checkpoint не восстановлены по обучающему скрипту.
- GPU/CUDA/H200, Linux-контейнер, расход ресурсов и лимит времени на целевой машине: Docker/GPU здесь недоступны. Dockerfile и CI подготовлены, но их наличие не означает успешную сборку.
- GitHub Actions не запускался: целевой репозиторий не доступен подключённому аккаунту. Код, данные и задачи во внешние сервисы не отправлялись.

Завершение инфраструктуры отделено от завершения хакатонного решения. Следующий критический этап — проверенный манифест анатомии/стороны, обучение всех пяти нарушений и валидация по исследованиям.

## Контрактные исправления API и архивов — 25 сентября 2026

- Полный прогон `python -m pytest -q`: **131 passed** (128 прежних + 3 новых),
  одно прежнее стороннее предупреждение Starlette/AnyIO.
- `path_to_study` в ответах `/v1/batch` и `/v1/review` теперь равен пути внутри
  архива (или имени загруженного файла). Служебный префикс `NNNN/extracted/`
  в CSV больше не попадает; префикс `NNNN/` добавляется только при совпадении
  путей внутри одного пакета. Проверено тестом и ручным запросом: архив с
  `study1/a.dcm` даёт строку `study1/a.dcm`.
- `safe_extract_zip` пропускает служебные записи файловых менеджеров
  (`__MACOSX/`, `._*`, `.DS_Store`, `Thumbs.db`), поэтому мусор из macOS-архивов
  не превращается в строки `Failure`. Новый тест проверяет пропуск и сохранение
  полезного файла.
- Причина изменения: аудит контракта выявил расхождение README («путь внутри
  архива») с фактическим выводом API и загрязнение результатов служебными
  файлами при упаковке тестового архива на macOS.
