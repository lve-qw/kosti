# Автоматическое развёртывание

GitHub: `lve-qw/kosti`. Основная ветка: `codex/output-contract-foundation`.
Каждый push проходит pytest и сборку CPU Docker-образа. Только успешный push
в основную ветку запускает деплой на `masha@158.160.203.10`.
Pull request и другие ветки проходят CI без изменения сервера.

GitHub Secrets: `KOSTI_DEPLOY_KEY` и `KOSTI_KNOWN_HOSTS`. Отдельный SSH-ключ
ограничен forced command `/usr/local/bin/kosti-ci-deploy`, без forwarding/PTY.
Host key закреплён. Секреты отсутствуют в репозитории.

Скрипт принимает SHA коммита и архив `git archive` по stdin, сериализует
деплои через flock, собирает образ с тегом SHA и проверяет `/ready` на
loopback-порту 18000. Затем заменяет контейнер `kosti` на порту 8000.
Если новая версия не готова, скрипт возвращает прежний контейнер.
Переключение требует короткой остановки сервиса.

Модель остаётся в `/home/masha/kosti-deploy/models`, подключается read-only
и не заменяется обновлением кода. Исходные исследования и ключи не входят
в архив деплоя. Проверка готовности включает загрузку и проверку хеша весов.

Рабочий контейнер: непривилегированный пользователь, read-only rootfs,
ограничения RAM 2 GiB и 256 процессов, `unless-stopped`, без capabilities.
Это демонстрационный HTTP-сервис. Для персональных медицинских данных
нужны HTTPS и контроль доступа.

Проверка: `docker logs kosti`, `docker inspect kosti`, `/health`, `/ready`.
Старые образы с SHA сохраняются для диагностики и восстановления. Контролируйте
свободное место на сервере и удаляйте только проверенные неиспользуемые версии.
Изменения самого установленного deploy-скрипта требуют отдельной установки
администратором: CI-ключ не имеет права заменить forced command.
