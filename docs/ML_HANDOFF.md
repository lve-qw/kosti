# ML: текущий контракт и задачи на GPU

Это подготовленный код инференса и оценки, **не обученная модель качества**.
`model_classifaer.pth` классифицирует только анатомию. Для его использования
нужно подтвердить порядок классов и исходную предобработку; автоматически их
не угадываем. Текущий адаптер поддерживает только описанную ниже предобработку:
если исходная отличается, восстановить её или переобучить классификатор.

## Bundle schema v1

JSON-манифест рядом с файлами весов содержит обязательные поля:

- `schema_version`: 1; `kind`: `quality` (либо `anatomy` для отдельного адаптера).
- `architecture`: `resnet18`; `weights`: относительный путь внутри каталога bundle;
  `weights_sha256`: SHA256 содержимого весов.
- `anatomy_classes`: две точные строки из `contracts.SPINE` / `contracts.HIP`
  **в порядке выходов обученной модели**.
- `preprocessing`: `mode="minmax_letterbox_rgb"`, `interpolation="bilinear"`,
  `size` (32–2048), `padding_value=0`, явные трёхкомпонентные `mean`, `std`.
- Для quality: `quality_regions=[SPINE,HIP]`, `quality_thresholds` (2 числа),
  `violation_labels` (5 пар область/тип из `ml.VIOLATION_LABELS`),
  `violation_thresholds` (5 чисел). Пороги строго между 0 и 1.

Строки SPINE/HIP здесь обозначают **значения констант**, не английские сокращения.
В манифесте нет неявных значений по умолчанию. Веса — непосредственно state_dict,
загрузка строго `torch.load(weights_only=True, map_location="cpu")`. Сеть ничего
не скачивает. Хеш проверяет целостность, не качество или происхождение модели.

`build_quality_model()` создаёт ResNet18 без загрузки предобученных весов.
Его fc имеет 9 выходов: `0:2` — анатомия в порядке манифеста;
`2:7` — нарушения в фиксированном порядке: позвоночник укладка/ось/предметы,
бедро укладка/ROI; `7:9` — общее качество позвоночник/бедро.
Две метки укладки различаются областью. Anatomy-only ResNet18 имеет fc из 2 выходов.

Предобработка получает уже декодированные и приведённые к корректной фотометрии
пиксели, minmax в [0,1], билinear resize без изменения соотношения сторон,
центральный квадратный padding нулями, повтор grayscale в RGB, затем mean/std.
Константные и нечисловые изображения отклоняются. Сохранять эту же процедуру
при обучении. Не растягивать анатомию; избегать поворотов/обрезок без смены меток.

`load_quality_predictor(path)` возвращает объект общего Predictor-контракта.
`quality_prob` берётся из отдельной бинарной головы соответствующей области;
`quality_class` итогового pipeline определяется OR пороговых нарушений.
Пороги качества в манифесте нужны для отдельного анализа бинарной головы,
не переопределяют правило формирования `quality_class`.
При расхождении бинарной головы и OR нельзя выдумывать тип нарушения.

## Перед запуском обучения

1. Утвердить манифест с path, study_uid, image_uid, pixel_hash, исходной папкой
   исследования, Excel-строкой, областью, стороной для соединения разметки,
   пятью nullable метками и итоговой nullable меткой качества. Подтвердить
   соответствия картинок области/стороне; сохранить источник и способ проверки.
2. Не заменять пропуски нулями. Неприменимые метки другой области — NaN.
   Три противоречивые экспертные строки сохранить и флагировать отдельно.
3. Удалить точные копии только из обучения, не из выходного CSV.
   `grouped_folds` объединяет исследования и совпавшие пиксели транзитивно.
   Он не стратифицирует редкие классы: проверить распределение позитивов,
   зафиксировать разумные фолды и не выбирать их по полученным метрикам.
4. Все пороги/калибровку выбирать на внутренней валидации тренировочных групп;
   внешний fold использовать только для оценки. PatientID набора не позволяет
   надёжно исключить повторного пациента в разных исследованиях — ограничение.

## Следующие задачи ML-специалиста

- Реализовать обучающий entrypoint с seed, журналом фолдов, конфигурацией,
  сохранением OOF-предсказаний и bundle. Начать с ImageNet ResNet18 backbone;
  скачивание допустимо только при подготовке, готовый сервис работает offline.
- Маскированный BCE на пяти нарушениях и двух качествах, CE на анатомии.
  `masked_bce_with_logits` игнорирует NaN. Взвешивание редких позитивов выбирать
  по train fold; сначала проверить замороженные признаки и небольшие головы.
- Сравнить DINOv2 linear probe на тех же фолдах; другой backbone потребует
  отдельной версии адаптера, нельзя поместить его веса в ResNet bundle.
- Проверить бинарные F1/AUC, macro-F1 типов, чувствительность, специфичность,
  число позитивов и ошибок каждого типа. AUC без обоих классов — undefined.
- CI получать bootstrap по исследованиям; для дублей между исследованиями
  использовать объединённые компоненты. Публиковать число определённых выборок.
- Дать QA проверенные bundle и фиксированный небольшой holdout для проверки
  загрузки, воспроизводимости и end-to-end результатов. Прохождение unit-тестов
  не подтверждает клиническое качество, F1/AUC или время на целевом GPU.

## Реализованный baseline-entrypoint

`kosti training-config` создаёт конфигурацию из локальных путей и SHA256 весов.
`kosti train --config ...` выполняет только проверку. Реальная оптимизация требует
`--execute` и в текущем этапе не запускалась. Подробно: [TRAINING.md](TRAINING.md).
Реализованы фиксированные эпохи ResNet18, masked BCE + CE, frozen-backbone baseline,
групповые OOF и export schema v1; фактическое обучение и DINOv2 ещё не выполнены.
